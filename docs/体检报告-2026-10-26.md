# 昱时全面体检（2026-10-26）

范围：桌面版（Windows / Mac，`src/` + `desktop/`）、iPhone 网页版（`web/`）、云端（`cloud/` 数据库脚本、`web/supabase/functions/` 云函数）。

## 一、安全：没有发现泄露

- 仓库现有文件和全部 42 个历史提交里都没有密钥：没有 Supabase Secret / service_role key、AI 同步令牌、VAPID 私钥；`.env*` 从没提交过（`.gitignore` 已排除）。
- 数据库每张表都开了行级权限，只能读写自己账号的数据；合并函数校验账号，防止换账号时把上个账号的数据传上去。
- 客户端拒绝保存 Secret key / service_role key；AI 同步令牌云端只存哈希；推送函数用定时密钥并做了等时比较。
- 桌面版窗口全部开了沙盒和上下文隔离，有内容安全策略，禁止跳转外部页面、禁止打开新窗口、拒绝所有权限请求；提醒弹窗只用 textContent 写字。

## 二、卡顿：找到 4 个原因，都已修

| # | 问题 | 修法 |
| --- | --- | --- |
| 1 | 桌面版同时有好几个窗口在跑（桌面日历、管理窗口、一直待命的格内编辑器、日记 / 复盘 / 课程 / 体重小窗），**每个窗口都在各自同步**：各自订阅云端变化、各自每 45 秒把全部数据拉一遍，格内编辑器每次双击拿到焦点还要再同步一次。改一条日程会引发好几轮全量同步。 | 只让一个窗口负责同步（Web Locks 选出来，它关掉后另一个自动接手），其他窗口从本机存储拿结果；小窗口和格内编辑器从不同步。管理窗口照常显示“已同步”，“立即同步”按钮照常能用。 |
| 2 | 日期格测量“放不放得下”（完成栏 +N、“还有 N 项”、太短的画成色条）时，每个格子、每一条都是改一下样式马上读一次尺寸，浏览器每读一次都重新排版整页。 | 所有格子合在一起分步测：统一读、统一改，一次刷新只排版几次。截图对比改前改后显示完全一样。 |
| 3 | 每格判断“这条日程今天有没有”时，不重复的日程也要先解析两个日期。 | 不重复的直接比日期字符串。 |
| 4 | 每次同步都把**全部**日程上传一遍、再全部读回来。 | 只上传和云端不一样的；没有要上传的就不再读第二遍。 |

实测（模拟 3000 条日程，桌面日历 7 天视图翻页）：每次 200–370 毫秒 → 90–150 毫秒。600 条时本来就在 30 毫秒左右。

## 三、同步冲突和 bug：找到 5 个，都已修

| # | 问题 | 修法 |
| --- | --- | --- |
| 5 | 周次任务（含课程状态、体重）和复盘：**时间戳相同、内容不同**时，本机和云端判定谁赢的规则不一样，两台设备会永久各显示一套。自动排的周次任务最容易碰到（时间戳固定是周一 00:00，两台设备各排一次时间可能不同）。 | 本机按规则胜出时把时间戳推后 1 毫秒再上传，云端收下后所有设备换成同一份。 |
| 6 | 云端返回的字段顺序和本机不同，周次任务 / 复盘 / 日记有一部分数据**每次同步都重复上传**（云端不变，白白浪费流量）。 | 按内容比较，不看字段顺序。 |
| 7 | 桌面版同步进行中又改了东西，这次改动要等最多 45 秒才上传。 | 同步结束马上补一次（手机版本来就这样）。 |
| 8 | AI 同步接口（邮件自动入日程用的）读和写之间如果电脑或手机刚改过同一条，会被**直接覆盖**。 | 写之前检查云端版本，有变化就整批不写，返回 409 让调用方重新读取。 |
| 9 | AI 同步接口的 upsert 会改写**已完成**的日程（10/21 同一封邮件里的新事项把已完成的旧日程改掉了）。 | 已完成的不改，返回 `skipped_completed`；确实要改传 `force: true`。接口说明已更新。 |

另：云端提醒每分钟重算到点提醒时，“已经发过”被记成失败，日志里全是假失败，已改成不记。桌面体重小窗也不再参与自动排周次任务（和其他小窗一致）。

## 四、生效方式

- 桌面版（Windows / Mac）：合并后重新打包。
- iPhone 网页版：合并后重新发布网页（第 1、4、5、6 条对手机也生效）。
- 云函数（第 8、9 条和提醒日志）：合并后要重新部署 `ai-sync` 和 `shiri-reminders`（先 `node web/scripts/sync-shared.mjs`）。数据库不用改。

## 五、没有改、需要知道的

- Supabase 的 Site URL 还是 localhost：注册确认邮件里的链接可能打不开（重置密码不受影响，代码里写了正确地址）。要在 Supabase 后台 Authentication → URL Configuration 改成 `https://yuquanzhao9.github.io/yushi-app/`。
- 所有同步都按“谁的修改时间新谁赢”，设备时钟差很多时可能选错版本。电脑和手机都开着自动对时就没问题。
- 桌面版打包后的主程序脚本超过 500 KB，对桌面程序没有实际影响，没有拆。
